# 卫戍协议 · 网页联合模拟

这是独立于原单机入口的联机版本。网页计算各自战斗，Node.js 服务端管理房间、公共选择、联防交接、生命与赏金结算，以及共同 Boss 血量。

## 运行

需要 Node.js 22 或更新版本。仓库原有 `dist/` 与 `dist/assets/` 必须在同一目录中存在；这不是仅拷贝 `multiplayer/` 就能独立运行的游戏数据包。

在仓库根目录执行：

```bash
npm ci --prefix multiplayer
npm start --prefix multiplayer
```

本机打开 `http://localhost:8080/`。队友打开 `http://服务端局域网IP:8080/`，在连接页填入服务端 IP 和端口。一人创建房间，其他人输入其房间号进入；2–4 人入房后，房主选择难度/地图并开始选择策略。

客户端入口为 `multiplayer/index.html`，服务端根地址自动跳转到这个入口。页面也有返回原单机的链接。**原单机大厅、源码、根 package.json 与构建脚本均未修改**，所以原 Pages 大厅尚没有新增按钮；可直接分享联机服务端网址。原单机可继续使用既有启动方式。

可通过环境变量更换监听地址和端口：

```bash
HOST=0.0.0.0 PORT=9000 npm start --prefix multiplayer
```

公网使用域名与受浏览器信任的 HTTPS/WSS。可以在反向代理上终止 TLS 并将 `/socket` 的 WebSocket Upgrade 转发到服务端；也可直接配置证书：

```bash
TLS_CERT=/path/to/fullchain.pem TLS_KEY=/path/to/privkey.pem PORT=8443 npm start --prefix multiplayer
```

HTTPS 页面不能连接普通 `ws://`。连接页会明确提示，局域网普通连接应使用服务端的 HTTP 页面。跨公网还需使相应监听端口可达。当前连接页从提供页面的服务端读取规则指纹，目标服务端必须使用同一套游戏资料和代码；推荐始终使用目标服务端提供的网页，不使用 `file://` 或原静态 Pages 托管联机入口。

## 游玩

- 昵称与头像在连接页设置；上传 PNG/JPEG/WebP 会居中裁切并压缩到 128×128。每位玩家可发送底部的固定表情。
- 入房后依次选择策略，全队不能重复；S.E.E.S. 的可见性仍由本地单机档案解锁标记控制。
- 备战买牌、刷新/冻结、升级、合成与装备数值沿用原规则。选择干员/召唤物后点击棋盘格位，再点击朝向确认部署；装备点选后点击干员，也可以拖到干员卡上。槽位满时，在干员档案中选择替换槽。
- 已放置的召唤卡跨回合保留，整备区上限、部署格位、装备绑定盟约与不占部署位特例由原会话模块判定。
- 点击玩家卡切换只读布阵/战斗视角；看队友时自己的战斗仍继续。
- 全体存活玩家准备后自动开战，准备后锁定本人的布阵；全体准备前可取消。开战前效果若产生奖励，需先领取再准备。联机固定 1 倍速，无个人暂停。
- 决策回合全队共用一次随机类型及六项候选，按每轮轮换的顺序各选一项、不重复。悬赏六项均为已准入精英，装备沿用早期1–3阶/后期5–6阶池，战术运营也用六项。
- 联防自动进入被选中者的视角，两人联防时左右显示两人的战场，**实际战斗按顺序接力**。第一人处理后漏出的敌人再交给第二人；另一侧显示等待/战后状态。
- 淘汰者留在房间观战，不再参与就绪与决策；剩余一人继续。最终共同击破 Boss 时，全队房间结果为成功。
- 结束页可导出包含本地阵容/战报和房间结果的 JSON，返回联机大厅。联机不会覆盖原单机存档或战绩。

## 已冻结的规则

1. 除以下差异，沿用单机难度倍率、资金、阶段与决策轮次，**不直接切换原表 `mode_multi_*`**。每人独立商店和库存，地图、波次种子、Boss 与盟约禁用一致。
2. 房主当前浏览器的敌人编制与禁用方案在开局冻结。波次配置影响实际生成；本地自定义的 Boss 血量倍率不参与联机计算。
3. Boss 初始生命 = 当前难度四人原表生命 × 0.75 × 人数倍率，2/3/4人分别为3/5/7倍，按开局人数固定，淘汰后不缩血。各自独立地图，共用血量；各自保留 `100+生命` 时限及漏怪扣秒。公共血量同步影响各地图的半血/形态条件。
4. 道中结束后才联防，仅本道中完整完成且零漏怪的玩家有资格。最多使用最快两人，按模拟耗时排序，同耗时按入房席位。无人完美则直接按各自漏怪结算。
5. 联防敌人从出生状态重新初始化，保留敌人种类、原始来源、悬赏标识和本轮基础倍率。联防者继续使用道中结束时同一个战斗对象，保留干员 HP/SP、召唤物、技能/再部署计时及部署费用，不允许重新布阵。联防不继续增加盟约层数。
6. 联防最后仍漏出的敌人，按 `lifePointReduce` 分别向原始漏怪玩家扣血，每玩家每轮最多10点。中间接力不扣血，联防者不承担他人的漏怪损失。超时场上的敌人及尚未出场的队列都进入交接账本；衍生敌人继承产生者来源。
7. 悬赏奖金归实际击倒者，使用原表数值，下轮入账。服务端按敌人实例去重，重发报告不会重复领奖。原装备“自身完美领奖”和鸭爵等策略奖励仍保留其原路由。
8. 最终 Boss 仍只开放原仓库已有昆图斯、卢西恩、萨米的意志；昆图斯子代豁免、未闭环的隐秘核心/其它 Boss 与 Spine 范围没有扩大。

## 断线与恢复

短时断线保留玩家席位与身份两分钟。原页面仍保有内存会话；刷新同一标签页通过 `sessionStorage` 重连凭证与恢复点恢复，服务端另保留最近收到的本人恢复点。恢复后按服务器阶段和任务 ID 补交报告，旧任务与重复悬赏不会重复结算。信标转交使用原有 inbox/outbox 接口并按 transferId 去重。

超过两分钟则淘汰断线玩家；联防进行中断线超时，其尚未完成的整批任务转交下一名联防者，没有下一人则按原来源结算。策略选择阶段缺席超时会结束房间，避免默默替玩家选策略。主动离房也结束其参与资格。

服务端房间与恢复点保存在内存中，**服务端重启不会恢复正在进行的房间**。浏览器后台定时器会补帧，但操作系统彻底挂起页面时仍需回前台继续计算；不会伪造一个已经完成的战斗结果。

## 代码与维护

| 路径 | 职责 |
| --- | --- |
| `server/index.js` | HTTP/HTTPS 静态分发、WebSocket、规则指纹、连接限额与心跳 |
| `server/rooms.js` | 房间阶段、轮选、就绪、联防任务、来源扣血、赏金、公共Boss、重连 |
| `shared/rules.js` | 纯规则、六候选生成、人数倍率与结算 |
| `shared/protocol.js` | 网络格式边界与头像规范 |
| `client/session.js` | 复用原会话/战斗的局部子类、可靠敌人账本、联防续战、BossHP接线、恢复点 |
| `client/connection.js` | 连接、重连与身份凭证 |
| `client/app.js` | 联机页面、就绪/操作门禁、观战与本地30Hz推进 |
| `client/board.js` | 只读快照与画布，不复算队友战斗 |
| `tests/` | 真实引擎、房间规则、真实WebSocket与多浏览器回归 |

关键规则边界有中文注释。适配没有全局修改 `NativeSession.prototype` 或原战斗原型。后续合并单机上游后，特别核对原 `NativeEconomy.beginBattle` 的准备期效果、`NativeBattle.prepareWaves/prepareFinalBoss`、漏怪退出、敌人路径与存档恢复接口；这些是联机适配的明确契约。

战斗结果由各自浏览器计算；服务器验证身份、任务、阶段、来源和重复报告，不在服务器重跑完整战斗，因此不保证对恶意篡改浏览器的玩家进行完整防作弊。本方案用于朋友间联合游玩。
